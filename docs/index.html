APS Digital Twin on AWS

A plant-floor digital twin: live IoT telemetry overlaid on an Autodesk Platform Services model, stored in Amazon Timestream for InfluxDB, and queried in natural language by an Amazon Bedrock AgentCore agent.

Architecture

Left-to-top-to-bottom flow: edge sensors → AWS IoT Core → Amazon Timestream for InfluxDB (in a Multi-AZ VPC) → query API → a Bedrock AgentCore agent → the APS viewer + chat in the browser.

How the data flows

  1. Edge: plant sensors / PLCs publish telemetry (temperature, humidity, vibration) via Telegraf using InfluxDB line protocol.
  2. Ingest: AWS IoT Core receives MQTT messages; an IoT Rule routes them to a writer.
  3. Store: an AWS Lambda writer batches points (5,000 lines/request, gzip) into Amazon Timestream for InfluxDB — a managed InfluxDB 2.x engine in a Multi-AZ VPC, listening on port 8086.
  4. Serve: a query Lambda runs Flux queries and exposes them through Amazon API Gateway.
  5. Intelligence: a Bedrock AgentCore agent (Strands + tools) reads the telemetry through that API and reasons with Amazon Bedrock (Claude) to answer natural-language questions.
  6. Present: the APS Viewer renders the model (translated by APS Model Derivative), overlays live sensor sprites/heatmaps, and hosts the Gen-AI chat. Served via CloudFront + S3, secured with Amazon Cognito.

Why Amazon Timestream for InfluxDB

Open-source APIs

Managed InfluxDB 2.x — existing Telegraf, client libraries, Flux/InfluxQL, and dashboards work unchanged.

Real-time performance

Single-digit-millisecond queries over high-cardinality time series — ideal for a live plant-floor twin.

Managed & durable

Automated backups, version upgrades, and Multi-AZ replication; db.influx instance classes, up to 16 TiB.

Pay for use

Billed per instance-hour + storage + data transfer — no upfront investment.
